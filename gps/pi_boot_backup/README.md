# Pi boot config backup — pre UART-routing fix (2026-09-13)

Exact snapshot of the Pi's **real** boot files, pulled live via SSH before editing them,
kept here for rollback since `/boot/firmware/` on the Pi is not git-tracked.

- `config.txt.pre-uart-fix` ← `/boot/firmware/config.txt`
- `cmdline.txt.pre-uart-fix` ← `/boot/firmware/cmdline.txt`

## Why this backup exists

Investigation (this session) found that `/boot/config.txt` (note: **not**
`/boot/firmware/config.txt`) contains a stale, inert block someone added in a previous
session:

```
# GPS UART - deshabilitar BT para liberar ttyAMA0
dtoverlay=disable-bt
enable_uart=1
dtoverlay=i2c-gpio,bus=2,...
```

`/boot/config.txt` is the Raspberry Pi OS deprecation stub ("DO NOT EDIT THIS FILE, moved
to /boot/firmware/config.txt") — it lives on the root ext4 filesystem, not on the FAT boot
partition (`/dev/mmcblk0p1`, mounted at `/boot/firmware`), so the bootloader never reads it.
The `disable-bt` fix was written to the wrong file and never took effect. The M8N GPS is
still on the mini-UART (`/dev/serial0 -> ttyS0`), whose clock derives from the core/VPU
clock and can drift under CPU frequency scaling — a known cause of intermittent UBX/NMEA
framing corruption, and the leading suspect for BACKLOG.md's BL-GPS-06 (gpsd losing TPV
mid-ride, ~22% stale).

`/boot/firmware/cmdline.txt` also still has `console=serial0,115200` — the kernel serial
console is configured on the same wire the GPS uses.

## The fix (applied after this backup was committed)

1. Add `dtoverlay=disable-bt` to the `[all]` section of the **real**
   `/boot/firmware/config.txt` (next to the existing `enable_uart=1`).
2. Remove `console=serial0,115200` from `/boot/firmware/cmdline.txt`.
3. Reboot, then verify `/dev/serial0` resolves to `ttyAMA0` (PL011) instead of `ttyS0`
   (mini-UART), and `hciconfig` no longer shows `hci0`.
4. Update `/etc/default/gpsd` (`DEVICES=`), the `99-ttyS0-gps.rules` udev rule, and
   `main.py`'s `_sleep_gps()` (`GPS_PORT = '/dev/ttyS0'`, main.py:688) to point at the new
   device path — all three currently hardcode `/dev/ttyS0`.

## Rollback

If the Pi fails to come back up cleanly (unlikely — `enable_uart=1` was already present
and correct; this only adds `disable-bt` and trims `cmdline.txt`), restore from this
backup:

```bash
ssh pi@pi-ecm "sudo cp /boot/firmware/config.txt.bak-preuart /boot/firmware/config.txt && \
               sudo cp /boot/firmware/cmdline.txt.bak-preuart /boot/firmware/cmdline.txt && \
               sudo reboot"
```

(on-device `.bak-preuart` copies are made immediately before editing, in addition to this
git-tracked copy — two independent rollback paths).
